## 2. HQ 실측 — 두 사이트를 같은 자로 잰 결과

같은 분야, 같은 저자, 같은 기간. 결과만 다르다.

| | **fairwayeta.com** | **faircast.kr** |
|---|---|---|
| 발행 편수 | 72 | 64 |
| **색인된 페이지** | **82** | **18** (GSC 표기 17) |
| 클릭 | **792 / 28일** | **46 / 3개월** |
| 추세 | 클릭 **+85%** · 노출 **+51%** | 색인 54 → 34 → 24 → **18 (단조 감소)** |
| 광고 | AdSense 코드 게재 중 | 5개월간 **4회 거절** |

**월 환산 클릭으로 보면 대략 fairwayeta 800 대 faircast 15다. 50배 차이다.**

이 레포 원장(`claude/STATUS.md` §1)의 색인 추이가 결정적이다.
**6/5에 54편이던 색인이 8/24에 18편으로 줄었다.** 글을 더 쓰는 동안 색인은 3분의 1이 됐다.
구글이 이 도메인에서 **적극적으로 페이지를 빼고 있다**는 뜻이다. 콘텐츠를 더 넣어 뒤집는 문제가 아니다.

원장 자체도 같은 의심을 이미 적어놨다 — 8/24 색인 요청 결과가 그대로면
**「원인이 도메인 이력 쪽」**이라고. 그 재측정이 아직 기록되지 않았다(§6-1).

## 3. 🔴 HQ가 가장 강하게 짚는 것 — AdSense 계정 리스크

이 레포 원장 §4 「절대 금지」에 이미 이렇게 적혀 있다:

> **애드센스 재신청** — 색인 지표 회복 전까지. **5번째 거절은 계정에 누적된다.**

여기에 이 레포가 모르는 사실이 하나 붙는다.
**fairwayeta.com에 AdSense 코드가 실제로 게재돼 있다** (`ca-pub-9894725798878226`, 2026-09-18 실측).

즉 AdSense 계정은 이제 **비어 있는 계정이 아니라, 성장 중인 사이트 하나를 물고 있는 계정**이다.
faircast 재신청은 예전처럼 「되면 좋고 안 되면 말고」가 아니다.
**거절·정책 이슈가 계정 단위로 쌓이면 fairwayeta 쪽 수익 경로까지 같이 흔들린다.**

> ⚠️ **미확인:** fairwayeta의 AdSense가 실제 승인·게재 상태인지는 코드 존재만 확인했고
> 대시보드 확인은 안 했다. **AdSense 대시보드에서 사이트 상태부터 확인할 것.**
> 이 확인 전에는 faircast 관련 AdSense 조치를 아무것도 하지 말 것.

## 4. 🔴 "폐쇄"는 최소 세 갈래다 — 뭉뚱그리면 사고 난다

이 레포 이름이 `ship-fairtech-assets`인 것이 핵심이다. **이건 사이트가 아니라 CDN 원본이다.**

| 대상 | 내리면 무슨 일이 | 되돌리기 |
|---|---|---|
| ① **WordPress 사이트**(가비아 호스팅) | faircast.kr 접속 불가 | 백업 있으면 가능 |
| ② **faircast.kr 도메인** | URL 자체 소멸 | 만료 후 회수 어려움 |
| ③ **이 GitHub 레포** | **jsDelivr CDN 링크가 전부 죽는다** | 레포 복구하면 가능 |

**③이 함정이다.** 이 레포는 public이라서 jsDelivr가 서비스한다
(`SITE_REFERENCE.md` §1·§6). 그리고 원장 §4에 이렇게 적혀 있다 —
**「fairwayeta … 자산(이미지·SVG)은 받아 쓰되」.**

→ **fairwayeta가 이 레포의 jsDelivr URL을 참조하고 있을 가능성이 높다.**
레포를 지우거나 private으로 바꾸면 **fairwayeta 기사 이미지가 깨진다.**
지금 트래픽이 오르고 있는 그 사이트다.

**선행 확인 (레포 밖에서 해야 함):**

```
# fairwayeta / fairtech-homepage 레포 루트에서
grep -rn "jsdelivr" --include=*.tsx --include=*.ts --include=*.json . | grep -v node_modules
grep -rn "ship-fairtech-assets\|faircast-images" --include=*.tsx --include=*.ts . | grep -v node_modules
```

참조가 1건이라도 나오면 **레포 삭제는 선택지에서 빠진다.** 사이트를 닫아도 레포는 남긴다.

## 5. 🟠 fairwayeta 코드가 faircast를 직접 부르고 있다

fairwayeta 레포 실측:

- `src/app/api/faircast-monitor/route.ts`
- `src/app/api/faircast-monitor/post/[slug]/route.ts`
- `src/app/robots.ts` 가 위 두 경로를 크롤러에 **allow** 하고 있다

faircast를 내리면 이 엔드포인트는 **죽은 채로 남는다.** 순서가 중요하다:

> **fairwayeta 쪽 정리가 먼저, faircast 폐쇄가 나중.**
> 반대로 하면 fairwayeta에 500 응답하는 경로가 생기고, robots가 그걸 크롤하라고 계속 지시한다.

이 정리는 fairwayeta 대화창 몫이며, 이미 그쪽 의도서 §3-4에 항목으로 들어가 있다.

## 6. 결정 전에 채워야 할 빈칸

### 6-1. 🔴 8/24 색인 요청의 결과가 아직 기록되지 않았다

원장 §0 ⓪이 「다음 창의 첫 작업」으로 지정한 재측정이다. 8/31 갱신본에도 결과가 없다.
**3주가 지났다. 이 숫자 없이는 폐쇄 판단의 근거가 절반뿐이다.**

확인할 것: 색인 18 → 몇 편인가. 늘었으면 회복 가능성이 있는 것이고,
그대로거나 더 줄었으면 **도메인 이력 가설이 사실상 확정**된다.

### 6-2. 가치 있는 자산의 목록화

폐쇄하든 아니든, 버리면 다시 못 만드는 것이 있다:

- **항만 가이드(WP 페이지 522)** — 국내 무역항 행정 디렉토리. 빌드 파이프라인까지 갖춰져 있다.
  faircast 콘텐츠 중 **가장 대체 불가능**하고, 성격상 **faircall과 겹친다**
- 클릭은 0인데 노출은 나오는 글 3편 (`vetting 뜻` 31 · `p&i club` 28 · `용선료` 14) — 한국어 수요가 실재한다는 증거
- 이미지·SVG 자산 (jsDelivr) — §4 ③

### 6-3. 비용 (HQ 재무원장 실측)

| 항목 | 금액 | 만료 |
|---|---|---|
| 가비아 웹호스팅 (WP 베이직) | 4,950원/월 | 2027-05-05 |
| 가비아 도메인 faircast.kr | 21,000원/년 | 2027-04-11 |
| 가비아 SSL (Sectigo) | 금액 미확인 | 2027-06-04 |

**월 환산 약 6,700원.** 솔직히 말하면 **비용은 폐쇄 사유가 못 된다.**
faircall(월 8만원대)과는 자릿수가 다르다. 진짜 비용은 **주의력과 AdSense 계정 리스크(§3)**다.
「돈이 아까워서」로 결정 프레임을 잡으면 판단이 흐려진다.

## 7. 갈래 두 개 (이 레포 규칙대로 2개만)

### A안 — 단계적 폐쇄

1. 신규 발행 즉시 중단 (이미 7월부터 사실상 중단 상태)
2. 살릴 자산 회수: 항만 가이드 데이터, 노출 있는 글 3편, 이미지 목록
3. fairwayeta 쪽 `faircast-monitor` 정리 (§5) — **선행**
4. WP 사이트 정적 백업(HTML 전체 저장) → 레포에 보관
5. 가비아 호스팅 만료(2027-05-05)까지는 그냥 두고 **갱신하지 않는다**
6. 도메인은 만료까지 보유 → 만료 시점에 재판단
7. **GitHub 레포는 남긴다** (§4 ③)

- 장점: 되돌릴 수 있고, 만료일까지 시간이 있어 서두를 필요가 없다
- 단점: 2027-05까지 월 6,700원이 계속 나간다

### B안 — 보존 전환 (폐쇄 아님)

1. 신규 발행 중단 + **색인 회복 시도도 중단** (AdSense 재신청 영구 포기)
2. 사이트는 그대로 두되 **손대지 않는다.** 모니터·개고·색인 요청 전부 정지
3. 남은 색인 18편은 그대로 검색에 두고, 유입되면 fairwayeta로 가는 링크만 심는다
4. 만료일에 다시 판단

- 장점: 아무것도 잃지 않는다. 한국어 수요(§6-2) 데이터가 계속 쌓인다
- 단점: "언젠가 다시 하겠다"가 3년 가는 전형적 패턴. 주의력이 계속 묶인다

### HQ 의견

**A안.** 단 §6-1 재측정을 하고 나서다.

근거는 비용이 아니라 §2와 §3이다. 색인이 **단조 감소**하는 도메인은 콘텐츠로 못 뒤집는다.
그리고 지금은 이 사이트가 실패할 때 **혼자 실패하지 않는다** — AdSense 계정을 fairwayeta와
공유하고 있기 때문이다. 방치(B안)보다 **명시적으로 닫고 자산을 회수하는 편**이 깨끗하다.

다만 **도메인과 레포는 A안에서도 살려둔다.** 둘 다 되돌리는 비용이 비대칭적으로 크다.

## 8. 되돌릴 수 없는 것 — 실행 단계에서 금지

- **레포 삭제·private 전환** — §4 확인 전에는 금지. jsDelivr가 죽는다
- **도메인 즉시 해지** — 만료까지 두는 것과 비용 차이가 없다. 회수는 불가능하다
- **WP 사이트 삭제 후 백업 없음** — 정적 백업이 레포에 들어간 것을 **눈으로 확인한 뒤** 삭제
- **AdSense 5번째 재신청** — §3. 대시보드 확인 전 금지
- **WPCode 617 재활성화** — 원장 §4. 폐쇄 작업 중에 "어차피 닫을 거니 크롤 막자"는 유혹이 생기는데,
  **크롤 차단은 색인 제거가 아니다.** 이 사이트가 이미 10일 손해 본 실수다.
  닫을 때도 제거 신호는 **410 또는 noindex**다
