## 2. 작업 방식 (대표 지침 요약 — 전문은 claude.ai 프로젝트 지침 v7)

- 반말. 무조건 긍정 금지, 문제는 냉정하게 지적
- **옵션은 2개까지.** 3개 이상 제시 금지
- **작업 완료를 권유하지 않는다.** 시작·끝·커밋은 대표가 정한다
- 세션 저장 권유·선택창 금지, 불필요한 요약 금지
- 오더는 파일 1~2개 / 변경 2~3곳 단위로 쪼개서 Cursor Auto로. 디버깅·리팩터·아키텍처만 Claude Code
- 각 오더 끝에 **검증 명령어**(grep / build)를 넣는다
- 운영자 신상 노출 금지. 대외적으로 운영자는 「Fairtech」 팀

## 3. 검증 도구 신뢰도 (경험칙 — 순서대로 믿는다)

| 순위 | 도구 | 비고 |
|---|---|---|
| 1 | **Search Console 라이브 테스트 (렌더링된 HTML)** | 봇이 실제로 본 것. 최종 심판 |
| 2 | 브라우저 view-source | 사람이 보는 원본. 529 스니펫 오탐을 여기서 깼다 |
| 3 | `scripts/site-monitor.js` | 편하지만 **오탐 전과 3회.** 빨간불 뜨면 1·2로 재확인 |
| 4 | 프론트엔드 텍스트 복사 | SVG는 정상이어도 납작해진다. **깨졌다는 증거가 못 된다** |
| 5 | `web_fetch` | faircast.kr은 Wordfence가 막는다. **쓸 수 없다** (fairwayeta는 됨) |

**교훈:** 도구가 「실패」라고 말할 때 먼저 의심할 것은 사이트가 아니라 도구다.
3회 모두 도구가 틀렸다.

## 7. 이 원장의 한계 — 먼저 읽을 것

faircall 원장은 **device bridge**로 Claude가 디스크를 직접 고친다. faircast는 **그 통로가 아직 없다.**
대표가 파일을 내려받아 옮겨야 하고, 그러면 두세 번 만에 안 하게 된다.

**이 원장이 굴러가려면 데스크톱 앱 연결이 선행 조건이다.** 연결 전까지는 갱신 누락을 전제하고 읽는다.
