# 색인 진단 — 왜 64편 중 18편만 색인됐나

2026-08-24. Search Console 커버리지 드릴다운 5종 + REST 전수 대조로 실측했다.

관련: `docs/AUTOMATION_POLICY.md` · `docs/BACKUP.md`

## 1. 숫자 정리

| 구분 | 수 |
|---|---|
| 발행 글 | 64 |
| 색인됨 | **18** (GSC 표기 17) |
| 크롤링됨 — 색인 안 됨 | 41 (전체 91 중 우리 글) |
| 발견됨 — 크롤 안 됨 | 5 |

나머지 미색인 항목은 **전부 의도된 상태**다. 손대지 않는다.

| 항목 | 수 | 상태 |
|---|---|---|
| 404 | 24 | 옛 월드컵 URL. 현재 **410 Gone + noindex** 응답 |
| 리디렉션 | 4 | http→https · www→non-www |
| NOINDEX | 4 | 태그·카테고리 아카이브 (의도) |
| robots.txt 차단 | 6 | 월드컵 크롤 차단 (의도) |

⚠️ **404/410 은 재검토 요청 대상이 아니다.** 요청해도 통과하지 않고, 시간이 지나면 목록에서 빠진다.
GSC 의 「유효성 검사 실패함」은 「아직 404 다」라는 뜻이지 우리 잘못이라는 뜻이 아니다.

## 2. 기각된 가설 — 글 자체는 문제가 아니다

색인된 글과 안 된 글을 같은 지표로 비교했다. **차이가 없다.**

| 지표 | 색인됨 | 미색인 |
|---|---|---|
| 본문 평균 길이 | 7,169자 | 7,457자 |
| 요약 없음 | 0 | 0 |
| 카테고리 미배정 | 0 | 0 |
| 내부 링크 평균 | 1.6 | 2.0 |

**미색인 쪽이 오히려 길고 링크도 많다.** 「얇은 콘텐츠라서 색인이 안 된다」는 설명은 성립하지 않는다.
사이트맵 누락도 0건이었다.

## 3. 실제로 찾은 것 — 신호가 엉켜 있었다

### (1) noindex 카테고리가 사이트맵에 실려 있었다 — 조치 완료

카테고리 아카이브 11개는 noindex 인데 `wp-sitemap.xml` 에는 들어 있었다.
**「색인하지 마라」와 「색인해 달라」를 동시에 보내고 있었다.**

→ 스니펫 361 을 `Exclude Tags & Categories from Sitemap` 으로 확장. 사이트맵 83 → **72 URL**.
목록 역할은 색인 대상인 랜딩 페이지가 한다 — `/hello-korea-page/` · `/hello-world-page/` · `/port-guide/`

### (2) lastmod 가 단 두 날짜에 몰려 있다 — 되돌릴 수 없음

| lastmod | 글 수 |
|---|---|
| 2026-08-23 | 51 |
| 2026-08-04 | 13 |

64편 전부다. 두 번의 일괄 편집(「30초 정리」→「요약」 치환 등)이 **모든 글의 수정 시각을 같은 날로 밀어버렸다.**

구글 입장에서는 사이트 전체가 한꺼번에 바뀐 것으로 보인다.
**전면 개고한 4편이 오타 고친 47편과 구분되지 않는다.** 진짜 갱신 신호가 잡음에 묻혔다.

⭐ **규칙 신설 — 일괄 치환은 수정 시각을 건드리지 않는다.**
표현 통일·오타 같은 비실질 편집은 `modified` 를 보존한다. REST 로 고칠 때:

```
POST /wp-json/wp/v2/posts/<id>   { "content": "...", "modified": "<원래 값>" }
```

실질 개고만 수정 시각을 갱신한다. 그래야 「이 글이 바뀌었다」가 신호로 작동한다.

### (3) 도메인 이력

`/match/` · `/simulate/` · `/insights/` 계열 옛 월드컵 URL 이 404 24개 + 크롤링 이력 30개로 남아 있다.
사이트가 통째로 업종을 갈아탄 이력이고, 이건 시간으로만 풀린다.
